## Рекомендации по разработке

Язык кода
- Комментарии в коде — на английском.
- Общение в тасках/PR — на русском или английском.

Стиль кода
- ES Modules, явные экспорт/импорт.
- Имена: функции — глаголы, переменные — понятные существительные.
- Избегать магических чисел — выносить в `constants.js`.
- Предпочитать ранние выходы, плоские ветвления, ограничивать вложенность.
- Не ловить ошибки «впустую».

Архитектура
- Логика: `physics` (состояние/циклы) ↔ `player` (поведение) ↔ `levelGenerator` (данные) ↔ `renderer` (вид).
- Взаимодействия с DOM/Audio — через соответствующие модули (`ui`, `audio`).
- Не добавлять кросс-зависимости между невизуальными и UI-слоями лишний раз.

Рабочий процесс
- Ветки feature/bugfix: `feat/<short-name>`, `fix/<short-name>`.
- Мелкие PR (до ~300 строк). Держите изменения атомарными.
- В описании PR указывайте, что изменилось и почему.
- Правило: не пушить изменения без явной команды владельца проекта.
- Обновлять документацию (`README`, `ARCHITECTURE`, `CODEMAP`, `CONTRIBUTING`) при ключевых изменениях (контролы, скорость, UX, публичные API).

Тестирование
- Проверяйте локально в браузере: старт/пауза/смерть/портал/конец уровня.
- Следите за производительностью: 60 FPS на десктопе, стабильность на мобилках.

Добавление модулей
- Новые константы в `constants.js`.
- Новые игровые сущности: данные в генераторе уровня, отрисовка в `renderer`, поведение в `physics`/`player`, звуки в `audio` при необходимости.

Документация
- Обновляйте `ARCHITECTURE.md`/`CODEMAP.md` при изменении публичных API или потоков.
